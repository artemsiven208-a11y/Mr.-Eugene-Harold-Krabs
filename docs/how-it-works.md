# Как устроен бот

Этот файл объясняет проект разработчику. Здесь описано, куда приходит сообщение, где выбирается формат и в каком месте запускается сама конвертация.

## Общая схема

Работа с файлом проходит так:

1. Пользователь отправляет документ, фото, аудио или видео.
2. Обработчик Telegram скачивает файл в отдельную временную папку задания.
3. Модуль определения проверяет расширение, MIME-тип и первые байты файла.
4. Реестр ищет доступные направления для найденного исходного формата.
5. Бот показывает кнопки только для найденных направлений.
6. Пользователь нажимает кнопку или вводит формат текстом.
7. Выбранный конвертер запускается в отдельном потоке, чтобы не блокировать Telegram.
8. Результат отправляется документом, а исходный файл остаётся доступен для следующей конвертации.

Если пользователь отправляет новый файл, старое состояние заменяется новым. Временные каталоги удаляются при отмене и при очистке старых заданий.

## Запуск программы

Точка входа — `main.py`.

При запуске программа:

1. читает `.env`;
2. проверяет наличие `BOT_TOKEN`;
3. ищет LibreOffice и FFmpeg;
4. строит реестр доступных конвертаций;
5. регистрирует команды Telegram;
6. запускает long polling.

Настройки передаются обработчикам через данные Dispatcher. Поэтому обработчику не нужно самому читать `.env` или заново искать внешние программы.

## Что лежит в каталогах

### `bot/`

Здесь только Telegram-часть проекта.

- `bot/handlers/commands.py` — `/start`, `/help`, `/formats`, `/cancel` и кнопки главного меню.
- `bot/handlers/files.py` — получение файлов, скачивание из Telegram, показ кнопок и отправка результата.
- `bot/handlers/search.py` — кнопка «Другой формат», поиск по тексту и исправление опечаток.
- `bot/keyboards.py` — InlineKeyboard и обычная клавиатура главного меню.
- `bot/states.py` — состояния пользователя и очистка данных текущего задания.

Обработчики не должны содержать код преобразования. Они только принимают запрос, собирают контекст и вызывают реестр.

### `converters/`

Здесь находятся реальные обработчики форматов.

- `base.py` — общие типы: контекст операции, результат и ошибки конвертации.
- `registry.py` — список разрешённых направлений и выбор обработчика.
- `documents.py` — TXT, MD, HTML, RTF и DOCX.
- `images.py` — изображения через Pillow.
- `pdf.py` — чтение текста PDF и превращение страниц в изображения.
- `spreadsheets.py` — CSV и XLSX через openpyxl.
- `media.py` — аудио и видео через FFmpeg.

Каждый обработчик получает `ConversionContext`. В нём есть путь исходного файла, исходное имя, исходный и целевой формат, папка задания и тайм-аут.

### `utils/`

- `config.py` — настройки из `.env` и значения по умолчанию.
- `system_tools.py` — поиск LibreOffice и FFmpeg.
- `file_detection.py` — определение формата и категории файла.
- `file_manager.py` — безопасные имена, временные папки, проверка места на диске и очистка.
- `format_search.py` — нормализация названий и поиск похожих форматов.

### `tests/`

Тесты работают без Telegram. Они создают маленькие файлы, вызывают конвертеры напрямую и проверяют результат. Поэтому тесты не требуют токена.

## Как работает реестр

Реестр хранит запись из четырёх частей:

~~~text
исходный формат → целевой формат → подпись кнопки → функция
~~~

Например, для PNG регистрируются направления PNG → JPG, PNG → WEBP и PNG → PDF.

При построении реестра учитываются внешние программы:

- направления через Pillow, PyMuPDF, python-docx и openpyxl добавляются всегда;
- направления через LibreOffice добавляются только если `soffice` найден;
- направления через FFmpeg добавляются только если найден `ffmpeg`.

При отсутствии внешней программы связанные кнопки скрыты. Наличие программы проверяется при старте. Сам файл всё равно может оказаться повреждённым или несовместимым — такую ошибку обрабатывает конвертер.

## Как хранится состояние пользователя

После загрузки файла в FSM сохраняются:

- путь к временной папке;
- путь к исходному файлу;
- безопасное имя файла;
- исходное расширение;
- категория файла;
- идентификатор сообщения с кнопками.

FSM — это данные о текущем шаге диалога. Они хранятся в памяти Dispatcher отдельно для пользователя и чата. После перезапуска бота выбор нужно начать заново. Содержимое документов в базу данных не записывается.

Основные состояния:

- `waiting_format` — бот ждёт, когда пользователь напишет формат;
- `processing` — файл уже загружен и доступен выбор конвертации.

Callback-кнопки используют короткие значения:

- `convert:pdf` — запустить PDF;
- `search:other` — открыть текстовый поиск;
- `search_pick:jpg` — подтвердить найденный формат;
- `cancel` — удалить текущее задание.

Перед запуском повторно проверяется, что выбранное направление есть в реестре для текущего файла. Кнопки пока не привязаны к идентификатору задания: старая кнопка может примениться к новому файлу, если направление подходит. Поэтому после отправки нового файла следует пользоваться его меню.

## Как выполняется конвертация

Telegram-обработчики асинхронные. Тяжёлая синхронная функция вызывается через `asyncio.to_thread`, а количество одновременных операций ограничивается Semaphore.

Каждая функция конвертации должна:

1. прочитать файл из `ConversionContext.source_path`;
2. создать результат в `ConversionContext.output_dir`;
3. сохранить понятное имя и правильное расширение;
4. вернуть `ConversionResult`;
5. выбросить `ConversionError` с сообщением, которое можно показать пользователю.

Нельзя просто переименовывать файл. Если направление не имеет технического смысла, его не нужно добавлять в реестр.

### Документы

DOCX читается через `python-docx`. Без LibreOffice для DOCX → PDF сохраняются текст и таблицы через PyMuPDF. При наличии LibreOffice реестр использует его для более точного переноса оформления.

TXT, Markdown и RTF могут превращаться в PDF. HTML читается как документ и не исполняется как код.

### PDF

PyMuPDF извлекает текст или отрисовывает страницы. Если у PDF несколько страниц, изображения упаковываются в ZIP, чтобы Telegram не получил десятки отдельных сообщений.

Если текст не найден, бот сообщает, что файл может быть сканом. OCR в проекте нет.

### Изображения

Pillow исправляет ориентацию по EXIF. При сохранении прозрачного изображения в JPG подставляется белый фон. Для анимированного GIF при переходе в неподвижный формат берётся первый кадр, и бот сообщает об этом.

### Таблицы

CSV превращается в XLSX. XLSX с одним листом превращается в CSV, а таблица с несколькими листами — в ZIP с отдельным CSV для каждого листа.

### Аудио и видео

FFmpeg вызывается через subprocess без `shell=True`. Видео → MP3 выполняется с удалением видеодорожки, а не созданием пустого аудиофайла.

## Временные файлы и безопасность

Для каждого задания создаётся каталог с UUID внутри `temp/`.

Программа:

- удаляет опасные части имён и не даёт выйти за пределы каталога;
- проверяет максимальный размер файла;
- проверяет свободное место на диске;
- ограничивает время внешнего процесса;
- не записывает токен и содержимое пользовательских файлов в лог;
- удаляет старые каталоги при запуске;
- передаёт пути файлов внешним программам отдельными аргументами, без командной оболочки;
- Python-обработчики HTML извлекают текст, не запуская JavaScript. При наличии LibreOffice HTML → PDF выполняется через него.

LibreOffice и FFmpeg работают от имени пользователя системы. Отдельной песочницы и явной настройки блокировки макросов в проекте пока нет.

Если конвертация завершилась ошибкой, пользователю отправляется понятное сообщение, а техническая причина записывается в лог без содержимого файла.

## Как добавить новый формат

1. Выберите библиотеку или внешний инструмент, который действительно умеет нужное преобразование.
2. Добавьте функцию в подходящий файл `converters/`.
3. Функция должна принимать `ConversionContext` и возвращать `ConversionResult`.
4. Зарегистрируйте направление в `build_registry`.
5. Если нужен внешний инструмент, добавьте проверку его доступности в `system_tools.py`.
6. Добавьте тест с маленьким реальным файлом.
7. Обновите таблицу форматов в `README.md`.

Например, для нового направления CSV → JSON нужно добавить функцию в `converters/spreadsheets.py`, зарегистрировать `add("csv", "json", "JSON", csv_to_json)` и проверить, что результат действительно является JSON.

## Как проверять изменения

Из корня проекта:

~~~powershell
pytest -q
python -m compileall -q .
~~~

Для проверки конкретного поведения можно вызвать один тест:

~~~powershell
pytest tests/test_converters.py -q
~~~

Telegram проверяется отдельно: запустите `python main.py`, отправьте файл в чат, выберите формат и откройте полученный документ. Локальные тесты этот путь не проходят.

## Где менять настройки

Значения берутся из `.env`, их чтение находится в `utils/config.py`.

| Параметр | По умолчанию | Что меняет |
|---|---|---|
| `MAX_FILE_SIZE_MB` | 20 | Размер входного файла в МБ |
| `MAX_CONCURRENT_JOBS` | 3 | Сколько конвертаций могут выполняться одновременно |
| `TEMP_FILE_TTL_MINUTES` | 30 | Возраст каталогов для удаления при следующем запуске |
| `CONVERSION_TIMEOUT_SECONDS` | 120 | Тайм-аут LibreOffice и FFmpeg в секундах |
| `LIBREOFFICE_PATH`, `FFMPEG_PATH` | автоматический поиск | Путь к программе вручную |

Тайм-аут не останавливает Python-конвертеры. Очистка по возрасту выполняется при запуске бота; фонового таймера удаления пока нет. Команда `/cancel` очищает состояние и файлы, но не останавливает уже работающий поток или внешний процесс.

## Что делать при проблеме

- Если не появляется PDF для офисного файла, проверьте запуск `soffice --version`.
- Если не появляются кнопки аудио или видео, проверьте `ffmpeg -version`.
- Если бот сообщает о неизвестном формате, проверьте расширение и первые байты файла.
- Если Telegram не принимает результат, проверьте размер файла и логи процесса.
- Если изменился реестр, перезапустите бота: список доступных направлений строится при старте.
